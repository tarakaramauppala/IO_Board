## What changed since yesterday

### 1. One-click functional battery
- Single **Functional** run executes the full behavioral suite on **AI1–AI4** with no operator input.
- **Auto current injection** via the Waveshare Modbus AO module (per-channel AI→AO map).
- **Auto DT71 settings** for each test (relay ON>OFF / ON<OFF, per-output disable, siren mode/thresholds),
  each confirmed by the device's settings echo before grading.

### 2. Injector reliability
- Fixed the pymodbus API call (count keyword / device_id).
- Added **reconnect-on-failure**: a transient RS-485 drop now rebuilds the client and retries instead of
  wedging the rest of the run. (A mid-run dropout was root-caused to a loose connection.)

### 3. Adversarial grading audit (multi-agent workflow)
- The first full run flagged 6 non-PASS items. Each was independently verified by an agent that first
  argued it was a **real firmware defect**, then argued **test-bench artifact**, and decided on evidence.
- **Verdict: 0 firmware defects.** 3 were grading false-negatives, 1 an injector-headroom miss, 1 a
  stale-RTT-edge artifact, 1 the expected "no meter" REVIEW.

### 4. Grading fixes (`functest.py`)
- **`_grade_band` rewritten**: the firmware's own **RTT profile band + DT113 event** (and cloud
  `thresholdLevelType`) is now authoritative; the re-classified injected sample is a cross-check. This
  fixes false-FAILs where the injector's ±100–300 µA offset near a threshold flipped the verdict even
  though the device classified the level correctly. FAIL only when device band **and** sample agree it's
  wrong; a headroom miss is REVIEW, never a hard FAIL.
- **HIGH_HIGH / LOW_LOW inject margins** so the current clears the boundary instead of sitting on it.
- **Flush-before-inject** on level steps (the RTT reader continues from the last read, so stale
  idle/prior-step data was polluting `band`/`sample`).
- **T5 (disabled output)**: grade on the device's periodic **state**, flush the prior relay test's stale
  ON edge first, and treat the **laggy cloud `digitalOutput`** as info-only (it was causing a false FAIL).
- **Warm-up RTT drain** at battery start to clear cold-start backlog.

### 6. Siren/light voltage automation (GDM-8251A)
- `meter.py`: DC-volts read; **driver hardened** — 115200 baud (the unit's actual rate, not 9600),
  `SYST:REM` on open, query retries (GW-Instek swallows the first command), and reconnect-on-silence.
- `station.py`: `ctx.ask(want_volts)` now **auto-reads the DMM** so S6–S8 grade real voltage instead of
  REVIEW.
- **Confirmed end-to-end** on the ALARM output through the station:
  `Siren ON → 12.389 V (PASS), Siren OFF → 0.004 V (PASS)`.

### 7. Bench gotchas captured (cost us time today)
- GDM-8251A on this bench is at **115200**, not the driver's old 9600 default.
- **Verify the PSU output is ON before a run** — a powered-off board reads 0 V on the siren *and* makes
  the J-Link RTT capture throw. (A dead board sent us chasing a phantom siren fault.)
- **One meter reads one output at a time.** ALARM (siren) is covered; the **LIGHT** output needs a small
  SPDT relay mux or a second DMM to also be automated in one pass.
